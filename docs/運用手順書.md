# スタンプカレンダー — 手順書・運用方法

クライアントのみの Web アプリ（Vite + React）。サーバー・DB・外部連携はありません。データはブラウザの `localStorage` に保存されます。

---

## 1. 概要

| 項目 | 内容 |
|------|------|
| 名称 | stamp-calendar（スタンプカレンダー） |
| 用途 | 月カレンダーへのラベルスタンプ貼付、家計（収支）記録・月次集計 |
| 実行環境 | ブラウザ（スマホ想定の UI） |
| データ保存 | `localStorage`（端末・オリジン単位） |
| 同期 / バックアップ自動化 | なし（手動） |

### 保存キー

| キー | 内容 |
|------|------|
| `stamp-calendar:v1` | 貼り付けたスタンプ |
| `stamp-calendar:ledger:v1` | 収支エントリ |

同一オリジン（プロトコル + ホスト + ポート）でのみ共有されます。`localhost:5173` と本番 URL、またはシークレットウィンドウでは別データになります。

## 2. 開発環境のセットアップ

### 前提

- Node.js（検証例: v24 系）
- npm

### 初回セットアップ

```bash
cd "e:\projects\dev\カレンダー"
npm install
```

### 日常の起動・確認

| 目的 | コマンド | 説明 |
|------|----------|------|
| 開発サーバー | `npm run dev` | 既定 `http://localhost:5173`、ホットリロードあり |
| 本番ビルド | `npm run build` | 型チェック（`tsc -b`）後、`dist/` に出力 |
| ビルド確認 | `npm run preview` | `dist/` をローカルで配信して確認 |
| 静的解析 | `npm run lint` | oxlint |

スマホ実機で見る場合は、同一 LAN 上で Vite が表示するネットワーク URL を開くか、ブラウザのモバイル表示を使います。

## 3. 利用手順（操作）

### 3.1 カレンダー（スタンプ）

1. 下部のスタンプ台紙からラベルを日付へドラッグ → 貼付
2. カレンダー上のスタンプを別日へドラッグ → 移動
3. スタンプをタップで選択 →「コピー」→ 貼りたい日付をタップ → 複製
4. スタンプを選択 →「削除」
5. 日付をタップ（コピーモードでないとき）→ その日の収支シート

利用可能なラベル（`src/labels.ts`）:

仕事 / 私用 / 打合せ / 外出 / 勉強 / 健康 / 締切 / 遊び

タッチ操作は長押し（約 180ms）でドラッグ開始します。短いタップは選択・日付オープンです。

### 3.2 収支

**日付シート（カレンダーから）**

- 収入／支出の種別とカテゴリ、金額、メモを入力して追加
- その日の明細を確認・削除

**収支タブ**

- 表示月の収入・支出・収支サマリー
- 日別棒グラフ、カテゴリ別ドーナツグラフ
- 月全体の明細一覧（削除可）
- 同タブからも新規登録可

カテゴリ（`src/financeCategories.ts`）:

| 種別 | カテゴリ |
|------|----------|
| 収入 | 給与、副業、ボーナス、その他収入 |
| 支出 | 食費、交通、住居、光熱、日用品、娯楽、医療、その他支出 |

金額は正の有限数のみ保存されます。変更は自動で `localStorage` に書き込まれます。

## 4. 運用

### 4.1 日常運用

1. `npm run dev` で起動するか、ビルド成果物を静的ホストで公開する
2. ブラウザでアプリを開き、スタンプ・収支を入力する
3. 特別なバッチ・cron・サーバー監視は不要

### 4.2 デプロイ（任意）

バックエンド不要のため、静的ファイルの配信のみです。

```bash
npm run build
```

`dist/` を任意の静的ホスティング（GitHub Pages、Cloudflare Pages、Nginx など）に配置します。デプロイ設定ファイルはこのリポジトリには含まれていません。

注意:

- オリジンが変わると `localStorage` は別物になる（データは移行されない）
- フォントは Google Fonts（`index.html`）に依存。オフラインではフォールバックフォントになる場合あり
- PWA 用のテーマ色メタはあるが、Service Worker / manifest は未実装

### 4.3 バックアップ（手動）

定期バックアップの仕組みはないため、重要なデータは次のいずれかで退避してください。

**方法 A: DevTools から JSON をコピー**

1. アプリを開いた状態で開発者ツール → Application（またはストレージ）→ Local Storage
2. 該当オリジンを選択
3. `stamp-calendar:v1` と `stamp-calendar:ledger:v1` の値をテキストファイル等に保存

**方法 B: コンソールで一括エクスポート**

```js
JSON.stringify({
  stamps: localStorage.getItem('stamp-calendar:v1'),
  ledger: localStorage.getItem('stamp-calendar:ledger:v1'),
})
```

結果をファイルに保存します。

**復元**

```js
const data = /* 保存した JSON をパース */;
if (data.stamps) localStorage.setItem('stamp-calendar:v1', data.stamps);
if (data.ledger) localStorage.setItem('stamp-calendar:ledger:v1', data.ledger);
location.reload();
```

### 4.4 データ消失に注意する操作

次を行うとデータが消えます。

- サイトデータの削除 / Cookie 等の一括消去
- シークレット（プライベート）ウィンドウの終了
- 別ブラウザ・別端末への切り替え（同期なし）
- 開発時のポート変更などオリジンの変更

### 4.5 ラベル・カテゴリの変更

コード変更が必要です。

| 変更対象 | ファイル |
|----------|----------|
| スタンプラベル | `src/labels.ts` |
| 収支カテゴリ | `src/financeCategories.ts` |

既存データの `labelId` / `categoryId` と不一致になると、表示上の解決に失敗することがあります。ID の削除・変更時は保存済みデータの扱いを検討してください。

## 5. トラブルシューティング

| 症状 | 確認・対処 |
|------|------------|
| 再読み込みでデータが消えた | 別オリジン／別プロファイルの可能性。Local Storage のキー有無を確認 |
| スタンプ・収支が空で始まる | JSON 破損や不正スキーマは読み込み時に破棄され `[]` になる。バックアップから復元 |
| スマホでドラッグできない | 長押ししてから動かす。コピーは先にスタンプ選択が必要 |
| コピーできない | スタンプ選択 →「コピー」→ 日付タップの順になっているか確認 |
| `npm run build` 失敗 | `npm install` 後、TypeScript エラーを修正（`tsc -b` が先に走る） |
| フォントが崩れる | ネット未接続時は Google Fonts が取れない場合あり |
| カレンダーの金額表示と収支が違うように見える | スタンプと収支は別ストア。金額ヒントは ledger 由来 |
